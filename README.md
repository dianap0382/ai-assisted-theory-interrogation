# AI-Assisted Theory Development

This repository contains five case-level computational analyses developed for the research proposal AI-Assisted Theory Development: Interrogating Theory Through Its Computational Representation.

Using corporate venturing and organizational design as the empirical and theoretical settings, the analyses examine how computational representations can help interrogate existing theory by identifying patterns of recognition, differentiation, dynamics, and theoretical limits. Computational signals serve as diagnostic starting points for returning to the evidence, assessing alternative explanations, and considering theoretical elaboration, rather than as theoretical findings in themselves.

The repository supports reproduction of the specified case-level analyses, not reconstruction of the original literature and interview corpora or independent reproduction of researcher adjudication.

## Getting started

Use **Python 3.11 or later** (core scripts checked with Python 3.13.5). Create a virtual environment and install the dependencies listed in requirements.txt.

From the repository root, execute the following commands. The scripts access their inputs and save generated results within their respective case directories.

```bash
python -m venv .venv

# Windows: 
.venv\Scripts\activate

# macOS/Linux: 
source .venv/bin/activate

python -m pip install -r requirements.txt

# Core case-level analyses
python case1/scripts/run_case1.py
python case2/scripts/run_case2.py
python case3/scripts/run_case3.py
python case4/scripts/verify_case4.py
python case5/scripts/verify_case5.py

# Optional semantic embedding analyses
python case1/scripts/run_semantic_case1.py
python case3/scripts/run_semantic_case3.py
```

The core lexical analyses and indicator checks do not require pretrained models. The optional semantic analyses download the specified sentence-transformer models on first use.

Generated results are saved in each case’s outputs/ directory. Some additional files in these directories document supporting analyses and researcher adjudication rather than outputs regenerated by the listed scripts. The case-specific verification instructions identify which results can be reproduced and how they should be compared with the saved outputs.

## Case guide

The five cases illustrate how computational representations can support four epistemic functions of theory interrogation: recognition, differentiation, dynamics, and limits. Each analysis generates or examines diagnostic signals that require interpretation against the underlying evidence.

- **Case 1: Incentives | Recognition (preservation).** Examines whether incentive-related practices in corporate venturing are recognized by existing organizational design constructs. Run `case1/scripts/run_case1.py` for TF-IDF comparisons of theoretical anchors and literature-derived passages. Optionally run `case1/scripts/run_semantic_case1.py` for sentence-embedding comparisons. The evidence does not yet establish a qualified preservation finding.
- **Case 2: Autonomy | Differentiation (decomposition).** Examines whether established theoretical categories adequately distinguish dimensions of corporate venturing unit autonomy. Run `case2/scripts/run_case2.py` for candidate provenance checks, dictionary sensitivity, and lexical comparisons. The decomposition signal remains sensitive to representational choices. The original full-corpus clustering is not reproduced.
- **Case 3: Partner integration | Differentiation (recombination).** Examines whether empirical practices suggest connections between theoretical constructs that are ordinarily treated separately. Run `case3/scripts/run_case3.py` for dictionary screening and candidate similarity analysis. Optionally run `case3/scripts/run_semantic_case3.py` for embedding comparisons. Recombination is supported descriptively within one article, but independent recurrence has not been established.
- **Case 4: Early-stage investment | Dynamics (tension).** Examines tensions between formal investment authority and the organizational conditions required to sustain early-stage investment. Run `case4/scripts/verify_case4.py` to verify saved pseudonymized indicators and case-level distinctions. This case illustrates the full six-step theory interrogation cycle, including theoretical elaboration concerning buffering from the parent firm’s expectation horizon.
- **Case 5: Fast-track governance | Limits (candidate non-fit).** Examines whether an apparent mismatch between established theory and empirical practice indicates a theoretical limit. Run `case5/scripts/verify_case5.py` to check saved indicators and threshold sensitivity. Returning to the evidence shows that the fast-track procedure was proposed rather than enacted, so the candidate non-fit does not survive qualitative adjudication.

These analyses reproduce specified computational comparisons or verify saved indicators. They do not independently reproduce the qualitative adjudication or establish the theoretical interpretations. The accompanying technical documentation explains the analytical procedures, evidence, and qualifications.

## Reproducibility scope

The repository contains the data needed for the listed case-specific scripts. It does not reconstruct all source PDFs, original interview text, full-corpus clustering, or researcher adjudication decisions. Case 4 and 5 contain pseudonymized numeric segment indicators, not original quotations. Research context snippets in Cases 1–3 derive from published academic sources; attribution and reuse rights remain governed by the underlying publications. The analyses are diagnostic screens, not proof of causal mechanisms or a substitute for qualitative validation.

Detailed computational descriptions and decisions are summarized in `TECHNICAL_DOCUMENTATION.md`.
